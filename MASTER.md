# Veydria Cartography — Master Document

*Last updated 2026-05-08 · supersedes the scattered notes across `README.md`, `AGENTS.md`, and the HANDOFF series for high-level orientation.*

---

## 1. What this is

A two-output cartography system for the fictional continent of **Veydria**, driven by a single source-of-truth YAML file:

1. **Static parchment-style continental map** — generated by a Python pipeline (matplotlib + Voronoi + Shapely).
2. **Interactive web reference map** — Vite + React + Leaflet + D3, currently the primary product.

Both products consume the same `data/veydria-topology.yaml` so the static art and the interactive tool can never disagree. Worldbuilder is the upstream canonical repo; `scripts/sync-world-data.mjs` pulls from it.

The interactive map is intended as a **GM workbench** for tabletop sessions set in Veydria — not a player-facing atlas. The new player share mode (`#share=1`) is the controlled-export path, not the default.

## 2. The world (the "map idea" in one page)

Veydria is a roughly C-shaped continent wrapped around an enclosed sea, the **Aethelian Basin**. The basin is the continent's trade pivot — not a producer, but a neutral processor and certifier. Six port cities ring it, each with its own architectural tradition.

Outside the basin, the continent fragments into civilizations bounded by terrain: highland steppes north, oasis chains threading the southern desert, archipelagos west of the Halkar Straits. Trade routes the app surfaces (`Copper-for-Steel Road`, `Highland-Steppe Corridor`, `Coastal Monsoon`, `Caravan Thread`) are not generic D&D filler — each is a specific economic relationship that drives faction tension.

The interactive map exposes:
- ~3,050 features across 12 layer types
- 6 named civilizations
- Chokepoints (red), ports (yellow / red anchors), oases (green pins), sacred sites (blue / yellow stars), landmarks (white diamonds)
- Trade routes, rivers, faction overlay, terrain-cost heatmap

This is a worldbuilding artifact first; the cartography app is the lens through which a GM uses it.

### Data flow per interaction

- **Layer toggle** → `setLayers` → React effect → D3 overlay redraw (auto-recompute, no Recompute button needed).
- **Click feature** → `MapViewer` resolves nearest GeoJSON feature → `InfoPanel` opens with description, related features, linked notes.
- **Drop pin** → `findNearestFeature(x, y, features, 40svg)` auto-links if eligible → persisted to `localStorage:veydria-annotations-v2`.
- **Plan journey** → `findRouteWithFallback` (direct → 1-civ pivot → 2-civ pivot) → `buildDailyBreakdown` (deterministic weather, midpoint-bucketed encounters) → renders Route / Days / Encounters tabs.
- **Snapshot** → `html-to-image` rasterises the Leaflet container with all overlays baked in → clipboard or download, capped at ~6 MP.

## 6. Guided tour

**Shipped.** 8-step first-visit walkthrough implemented in `tour.ts` + `TourOverlay.tsx`. State managed by `tourReducer` in `App.tsx`.

**Trigger.** Checks `localStorage:veydria.tour.completed.v1`. If missing, fires on first frame after `loaded === true`. Auto-start is skipped on viewports `< 768 px` where the tour card is too cramped. Replay via KeyboardHelp (?) overlay.

**Mechanic.** Floating spotlight card with text + CSS `clip-path` dimming everything except the highlighted target. Next / Back / Skip buttons, plus arrow-key navigation.

**Steps:**

1. **Welcome** — centred card. "Veydria is a fantasy continent..."
2. **Layers panel** — highlights layer column. Suggests trying the `Politics view` preset.
3. **Cmd-K search** — highlights search button. Opens palette pre-populated with `oravan`.
4. **Click → info panel** — opens Aethelian Basin InfoPanel (falls back to first water/civilization feature if schema drift). *Step 4 fallback implemented.*
5. **Journey planner** — opens planner, explains route + days + encounters.
6. **Pins** — demonstrates dropping a pin near a feature.
7. **Player view** — toggles share mode, explains clean player URL.
8. **Done** — "Press `?` for keyboard help any time."

**Tests.** `tour.test.ts` verifies step graph integrity, reducer state transitions, localStorage completion, and mobile gating.

## 7. Conventions

- **Memory keys.** All `localStorage` reads use a versioned key (`veydria.X.vN`). When in doubt, additive change → defensive merge; breaking change → bump version.
- **Tests next to code.** `foo.ts` → `foo.test.ts`. Vitest globs `src/**/*.test.{ts,tsx}`.
- **No HANDOFF without a state-of-the-tree note.** Each handoff opens with branch / CI / tests state so a future instance can orient in 30 seconds.
- **The data/ folder is read-only.** Edits go to worldbuilder, then `npm run sync:data`. (One known gotcha: `web/public/veydria-schematic.svg` is a manual mirror of `data/veydria-schematic.svg`; the sync script doesn't touch it. If the SVG ever shows mojibake again, copy it over — that's exactly what happened on 2026-05-08.)
- **Off-peak preference.** Heavy / long-running work happens evenings, mornings, weekends per the global Money Rule. Mid-session reasoning stays on Sonnet 4.6 with `opusplan` reserved for cross-cutting refactors.
